# 2. M5 目标

M5 要把 M2 的“已审核维修记录”转化为稳定、可复用、可验证的正式统计能力，并完成成员内部排行榜闭环：

```text
APPROVED 且未软删除的维修记录
        ↓
唯一 Analytics Query / Repository
        ↓
个人正式统计 + 分类分布 + 月度趋势
        ↓
本月 / 本学期 / 总榜
        ↓
工作台排行预览 + 独立排行榜页面
```

M5 完成后应形成：

- 唯一、可测试的正式维修统计口径；
- 本月、本学期、全部时间三个统计范围；
- 按维修数量及维修时长查看排行榜；
- 个人排行、Top N、分类分布和月份趋势能力；
- M3 工作台和个人主页可无重复查询地接入 M5；
- 为 M7 官网公开统计提供受控 Service 契约，但本阶段不公开数据；
- GreatSQL 上可解释、可分页、稳定排序的聚合查询。

# 3. M5 范围

## 3.1 必须实现

### 正式统计

- 仅统计 `status = APPROVED AND deletedAt IS NULL` 的维修记录；
- 当前成员的累计维修数；
- 当前成员的本月维修数；
- 当前成员的本学期维修数；
- 当前成员的累计维修时长；
- 当前成员的故障分类分布；
- 当前成员最近 12 个自然月的维修趋势；
- 无数据、学期未配置、区块失败均有不同且明确的返回状态。

### 排行榜

- 本月榜；
- 本学期榜；
- 总榜；
- 默认按维修数量排序；
- 可切换按维修时长排序；
- 支持分页、Top N 预览和“我的排名”；
- 并列名次语义稳定；
- 仅返回内部展示所需的最小成员字段。

### 页面

- `/member/rankings` 内部排行榜页面；
- M3 `/member` 工作台将 `ranking` 占位替换为真实 Top 3/Top 5 预览及当前成员名次；
- `/member/profile` 接入分类分布和月度趋势；
- 他人内部主页只保留已授权的个人正式摘要；本阶段不强制展示他人的详细趋势和分类分布。

### 工程与质量

- 统计聚合在 GreatSQL 中完成，不把全量维修记录拉到 Node.js 内存计算；
- Contract、Service、Repository、Route、页面职责分离；
- 覆盖单元、契约、真实 GreatSQL 集成、权限、边界日期和并列排名测试；
- Desktop / Mobile、Normal / Dark 均可用；
- 不使用只靠颜色表达的名次、趋势或状态。

## 3.2 明确不做

- 不实现官网首页公开统计与公开排行榜，这属于 M7；
- 不决定或实现“公开真名 / 隐藏 / 仅昵称”的后台配置，这属于 M6/M7；
- 不实现评论、回复、@、通知、收藏，这属于 M4；
- 不实现管理员成员管理或统计配置后台，这属于 M6；

- 不引入 Redis、消息队列、定时离线计算或数据仓库；

- 不将草稿、待审核、退回或软删除记录纳入任何正式指标；

# 5. 统计口径与日期规则

## 5.1 唯一有效记录

所有正式统计必须以以下谓词为根：

```text
RepairRecord.status = APPROVED
AND RepairRecord.deletedAt IS NULL
```

附加条件只能缩小范围，例如：

- `memberProfileId = ...`；
- `repairDate >= startInclusive`；
- `repairDate < endExclusive`；
- `categoryId = ...`。

`DRAFT`、`PENDING`、`REJECTED` 和软删除记录一律不参与：

- 维修数量；
- 维修时长；
- 分类分布；
- 趋势；
- 排名与“我的排名”。

## 5.2 时间范围

统一范围：

```ts
type AnalyticsScope = "MONTH" | "TERM" | "ALL_TIME";
type UtcRange = {
  startInclusive: Date;
  endExclusive: Date;
};
```

规则：

- 本月按 `Asia/Shanghai` 当前自然月计算；
- 本学期复用 `ACADEMIC_TERM_START` / `ACADEMIC_TERM_END`；
- 所有日期范围转换为 `[startInclusive, endExclusive)`；
- 全部时间不附加日期条件；
- API 不接受客户端自报时区来改变正式口径；
- 测试必须固定 `now`，覆盖月初、月末、跨年和 UTC/CST 边界；
- 学期两项均未配置时，本学期统计和榜单返回 `UNCONFIGURED`，不得伪装为空榜或 `0`；
- 学期配置非法仍沿用 M3 的启动失败规则和 `ACADEMIC_TERM_CONFIG_INVALID`。

## 5.3 数量与时长

- 维修数量使用有效记录数；
- 维修时长使用 `SUM(durationMinutes)`，单位始终为分钟；
- 已通过记录的 `durationMinutes` 若因历史数据为空，聚合时按 `0` 处理，但应记录数据质量测试，不得导致整个榜单失败；
- API 返回整数分钟；小时只在 UI 展示层格式化，不改变排序值；
- 不使用浮点小时参与比较或排行。

# 6. 公共 Contract

所有跨模块类型继续集中在 `src/types/contracts.ts`。建议冻结以下语义，命名可按工程规范微调，但不得改变字段含义。

```ts
export const AnalyticsScope = ["MONTH", "TERM", "ALL_TIME"] as const;
export const RankingMetric = ["REPAIR_COUNT", "DURATION_MINUTES"] as const;
export const AnalyticsStatus = ["AVAILABLE", "UNCONFIGURED"] as const;

export type AnalyticsScope = (typeof AnalyticsScope)[number];
export type RankingMetric = (typeof RankingMetric)[number];
export type AnalyticsStatus = (typeof AnalyticsStatus)[number];

export type AnalyticsRange = {
  startInclusive: string | null;
  endExclusive: string | null;
  timezone: "Asia/Shanghai";
};

export type MemberAnalyticsSummary = MemberRepairSummary & {
  source: "M5_ANALYTICS";
};

export type CategoryDistributionItem = {
  categoryId: string | null;
  categoryName: string;
  approvedCount: number;
  durationMinutes: number;
};

export type MonthlyTrendPoint = {
  month: string; // YYYY-MM，按 Asia/Shanghai
  approvedCount: number;
  durationMinutes: number;
};

export type MemberAnalytics = {
  summary: MemberAnalyticsSummary;
  categoryDistribution: CategoryDistributionItem[];
  monthlyTrend: MonthlyTrendPoint[];
  generatedAt: string;
};

export type RankingEntry = {
  rank: number;
  memberProfileId: string;
  displayName: string;
  avatarUrl: string | null;
  approvedCount: number;
  durationMinutes: number;
  metricValue: number;
  isCurrentMember: boolean;
};

export type RankingResult = {
  scope: AnalyticsScope;
  metric: RankingMetric;
  status: AnalyticsStatus;
  range: AnalyticsRange;
  items: RankingEntry[];
  currentMember: RankingEntry | null;
  pagination: PaginationMeta;
  generatedAt: string;
  source: "M5_ANALYTICS";
};

export type MemberRankingPreview = {
  available: true;
  status: AnalyticsStatus;
  scope: "TERM";
  metric: "REPAIR_COUNT";
  leaders: RankingEntry[];
  currentMember: RankingEntry | null;
  generatedAt: string;

```

兼容要求：

- `MemberRepairSummary` 的四个既有指标字段含义不变；

- `MemberDashboard.ranking` 从 M5 的 `DeferredModule` 原子替换为 `MemberRankingPreview`；
- M4 的 `notifications`、`favorites` 字段不因 M5 改动；
- 后端 Contract、Route 和前端消费者应在同一个工作包中同步，避免中间态崩溃；
- API 响应继续使用 M0 的统一成功/错误信封与 `requestId`。

# 7. Query、Repository 与聚合实现

建议目录：

```text
src/features/analytics/
├─ analytics-repository.ts
├─ analytics-service.ts
├─ analytics-policy.ts
├─ analytics-view.ts
└─ ranking-service.ts
```

职责：

- Repository：GreatSQL 聚合、分组、分页和最小字段查询；
- Service：权限、范围解析、并列排名、区块组合与降级；
- Policy：内部可见性与展示名规则；
- View：数据库结果转换为稳定 Contract；
- Route：输入解析、Session、调用 Service、返回统一信封。

实现要求：

- 通过 `approvedRepairWhere()` 组合 Prisma 查询，或通过集中式 Analytics Repository 将唯一谓词封装一次；
- 不调用 `listApprovedRepairsForAnalytics()` 拉取全表后在 JavaScript 中 `filter/reduce/sort`；
- 分类分布在数据库中按 `categoryId` 聚合；
- 月度趋势由数据库按年月聚合，Service 补齐没有数据的月份为真实 `0`；
- 排行榜按 `memberProfileId` 聚合；
- 只纳入 `MemberProfile.status = ACTIVE AND deletedAt IS NULL` 的当前有效成员；历史已撤销成员的数据仍保留，但默认不进入当前成员排行榜；
- 所有聚合结果使用明确的数值转换，防止 GreatSQL `BIGINT/DECIMAL` 驱动值以字符串泄漏到 API；
- 任何 Raw SQL 必须使用参数化查询；禁止字符串拼接 scope、metric、日期或成员 ID；
- 若 Prisma 无法表达窗口函数，可使用受控、参数化的 `$queryRaw`，并为 SQL 单独写 GreatSQL 集成测试。

## 7.1 查询性能

先使用真实 GreatSQL 的 `EXPLAIN` 检查下列查询：

- 指定成员的全量/月度/学期统计；
- 指定范围的成员分组排行；
- 分类分布；
- 12 个月趋势。

现有索引不足时，才允许新增 Migration。候选索引方向：

```text
(status, deleted_at, repair_date, member_profile_id)
(member_profile_id, status, deleted_at, repair_date)
```

不得无证据同时添加多个重叠索引。交付报告必须附 `EXPLAIN` 摘要、数据量和最终选择。

# 8. 排行规则

## 8.1 入榜条件

- 当前范围内至少存在一条有效维修记录；
- 成员档案为 `ACTIVE` 且未软删除；
- 零记录成员不出现在榜单列表；
- 当前成员零记录时 `currentMember = null`，页面显示“当前范围暂无上榜记录”。

## 8.2 排序与并列

数量榜：

```text
approvedCount DESC
durationMinutes DESC
memberProfileId ASC
```

时长榜：

```text
durationMinutes DESC
approvedCount DESC
memberProfileId ASC
```

名次使用竞赛排名语义：主指标相同则名次相同，后续名次跳号。例如：

```text
10, 10, 8 → 1, 1, 3
```

次级指标与 `memberProfileId` 只用于稳定展示顺序，不改变同主指标的并列名次。

分页要求：

- 默认 `page=1&pageSize=20`；
- `pageSize` 范围 1–100；
- 相同请求在数据不变时顺序稳定；
- `currentMember` 不受当前分页影响；
- Top N 预览与完整榜单使用同一排名算法，不得分别实现两套逻辑。

## 8.3 展示名与隐私

内部排行榜展示名规则：

```text
nickname（非空）
↓
realName（非空）
↓
User.displayName（非空）
↓
“成员”
```

禁止返回：

- QQ 号；
- 手机号；
- 学号、班级；
- `User.id`；
- 登录凭据、账号状态细节；
- 审核备注、维修内部备注和审计内容。

M5 的内部展示名规则不是 M7 的公开隐私策略。M7 上线前必须另行实现管理员公开策略和公开 DTO。

# 9. API 任务

所有接口均要求有效 Session、ACTIVE User、ACTIVE MemberProfile，并要求内部读取权限。建议新增权限：

```text
analytics:read_internal
```

该权限授予 MEMBER、ADMIN；不得授予游客或仅有报名身份的用户。

## 9.1 当前成员统计

```http
GET /api/v1/member/analytics
```

返回：

- `MemberAnalytics.summary`；
- 分类分布；
- 最近 12 个月趋势；
- `generatedAt`。

## 9.2 内部排行榜

```http
GET /api/v1/member/rankings?scope=TERM&metric=REPAIR_COUNT&page=1&pageSize=20
```

参数：

- `scope`: `MONTH | TERM | ALL_TIME`，默认 `TERM`；
- `metric`: `REPAIR_COUNT | DURATION_MINUTES`，默认 `REPAIR_COUNT`；
- `page`: 正整数，默认 1；
- `pageSize`: 1–100，默认 20。

返回 `RankingResult`。

## 9.3 工作台聚合

```http
GET /api/v1/member/dashboard
```

调整：

- `repairSummary.source` 改为 `M5_ANALYTICS`；
- `ranking` 返回本学期维修数量榜预览；
- 学期未配置时返回 `available: true, status: UNCONFIGURED`，不返回虚假榜单；
- 排行区块失败时加入 `degraded`，但不得拖垮工作台其他区块；
- `degraded` 类型增加 `ranking`。

## 9.4 稳定错误码

优先复用：

- `UNAUTHENTICATED`；
- `FORBIDDEN`；
- `MEMBER_PROFILE_NOT_FOUND`；
- `MEMBER_PROFILE_INACTIVE`；
- `VALIDATION_FAILED`；
- `ACADEMIC_TERM_CONFIG_INVALID`；
- `INTERNAL_ERROR`。

仅在现有错误码无法表达时新增：

```text
ANALYTICS_SCOPE_INVALID       400
RANKING_METRIC_INVALID       400
```

错误响应不得返回 SQL、表名、堆栈、成员隐私字段或数据库连接信息。

# 11. 权限、安全与隐私

- Route、Service 两层均执行权限校验；
- 不允许通过修改 `memberProfileId` 查询任意成员的敏感统计详情；
- 排行榜只返回最小 DTO；
- 所有输入采用白名单 Enum，不将用户输入直接拼入 `ORDER BY`；
- API 不接受任意时间范围，避免越权导出式遍历；
- 日志不得记录完整榜单响应或成员隐私字段；
- 性能日志只记录 scope、metric、pageSize、耗时和 requestId；
- 统计读取不产生逐次业务审计日志，避免放大 `AuditLog`；
- 权限变更、未来公开策略变更仍由对应管理模块审计；
- 页面和缓存不得将内部榜单标记为公开缓存。

# 12. 缓存、并发与一致性

第一版以实时数据库聚合为准：

- 不新增跨请求持久化缓存；
- API 使用 `no-store` 或等价私有策略；
- 不把带 `isCurrentMember` 的响应放入共享缓存；
- 同一响应中的榜单列表与“我的排名”尽量在同一数据库快照/一致查询逻辑下生成；
- 维修审核通过、退回或软删除后，下次请求应反映最新结果；
- 并发审核的幂等性继续由 M2 保证，M5 不新增计数器写入；
- 禁止通过“审核时递增成员统计字段”维护冗余计数，以免回滚、退回和软删除导致漂移。

若真实数据量证明实时查询不可接受，先提交性能报告，再另行设计缓存或快照；不得在 M5 中无评审引入双写。

# 13. 数据库与 Migration

M5 默认不新增业务实体。

允许的 Schema 变更仅限：

- 经 `EXPLAIN` 证明必要的复合索引；
- 与现有命名规范一致的 Migration；
- 可在真实 GreatSQL 8.x 执行和回滚评估。

Migration 要求：

- 不修改历史 Migration；
- 不删除或重建生产业务表；
- 不使用 SQLite/PostgreSQL 方言；
- 索引名显式、稳定；
- 在交付报告记录执行时间、锁表风险和回退方案；
- `prisma migrate deploy` 与 `prisma generate` 均通过。

环境变量：

```text
ACADEMIC_TERM_START=YYYY-MM-DD
ACADEMIC_TERM_END=YYYY-MM-DD
```

M5 不新增可由请求参数或已有配置表达的环境变量。学期配置语义不得漂移。

# 14. 软删除与历史一致性

- `RepairRecord.deletedAt IS NOT NULL` 后必须立即退出所有正式统计；
- `MemberProfile.deletedAt IS NOT NULL` 或 `status != ACTIVE` 后不再进入当前成员排行榜；
- RepairRecord、MemberProfile 不做物理级联删除；
- 分类软删除后，历史记录仍按原分类关系统计和显示历史名称；
- 无分类的历史记录归入稳定的“未分类”桶，`categoryId = null`；
- 不因分类停用或成员撤销而篡改历史维修数据；
- M5 不新增可被手工修改的累计计数字段。

# 17. 验收标准

M5 只有在以下条件全部满足时才可验收：

- 本月、本学期、总榜均可按维修数量查看；
- 可切换维修时长榜；
- 排榜、我的排名、分页与并列规则一致；
- 个人累计/月度/学期/时长统计来自 M5 唯一 Analytics Service；
- 分类分布与 12 个月趋势可用，并与正式摘要口径一致；
- 只有 APPROVED 且未软删除记录进入统计；
- 学期未配置显示 `UNCONFIGURED`，不伪造 `0` 或空榜；
- M3 工作台排行占位被真实数据替换，失败可局部降级；
- QQ、手机号、学号、班级、`userId` 未进入排行榜 DTO；
- 查询在 GreatSQL 中聚合，未将全量记录加载到 Node.js 排序；
- 关键查询完成 `EXPLAIN`，无明显全表扫描风险或已说明合理原因；
- 无未经评审的统计快照表、双写计数器、Redis 或定时任务；
- Desktop / Mobile、Normal / Dark 验收通过；
- M0–M3 回归测试、lint、TypeScript、build、Migration 和真实 GreatSQL 测试通过；
- 完成 `docs/M5-交付报告.md`。

核心验收流程：

```text

```
